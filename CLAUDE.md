# Parsimony (раньше «Напоминалка») — контекст проекта для Claude Code

## Что это
PWA-календарь-планер **Parsimony** (название — константа `APP_NAME` в `js/core.js`; ключ данных и адрес сайта прежние). Пользуются на iPhone (установлено на экран «Домой») и на ПК в браузере.
Хостинг: GitHub Pages, репозиторий `greed1-alt/Pars1m0ny-s_helper`, ветка `main`, корень репозитория.
Адрес сайта: **https://app.parsimony.ru/** (с 9 октября 2026, см. «Свой адрес»). Старый https://greed1-alt.github.io/Pars1m0ny-s_helper/ сам перенаправляет туда.

## Файлы
Без сборщика: обычные `<script>` по порядку, у всех файлов общие глобальные переменные. Данные — в localStorage (ключ `remapp_v1`).
- `index.html` — разметка и подключение файлов.
- `css/app.css` — запасные дизайн-токены (`:root`, темы), календарь, окна. `css/sections.css` — разделы, графики, нижние вкладки. `css/ui2.css` — экраны интерфейса, карточки, оформление, подсказки «?».
- `js/core.js` — данные `S`, `migrate()` + `onMigrate()` для разделов, реестр действий `ACT`, иконки, даты, повторы, ввод фразой `parseNL`.
- `js/look.js` — оформление: палитры `PAL`, контраст, вид карточек, углы, цвет событий; `applyLook()` ставит цвета переменными CSS; блок «Оформление» в Настройках (`lookHTML()`).
- `js/help.js` — подсказки «?»: тексты `HINTS`, `hint(текст)` / `hintK(ключ)`, всплывающее окошко `#tip`.
- `js/calendar.js` — виды календаря, `render()`, боковая панель, карточка события, настройки, меню команд, `snap()`/`undo()`.
- `js/charts.js` — графики SVG (линия/волна, столбики, кольцо, «пончик») и подсказка при наведении.
- `js/sections.js` — переключение разделов `SEC`/`setSec`, плашка «Вы пропустили», пример для пробы, общие функции месяца и денег.
- `js/tasks.js`, `js/habits.js`, `js/finance.js` — разделы «Задачи», «Привычки», «Финансы».
- `js/goals.js` — раздел «Цели»: цели со сроком и шагами, темп, подначки и похвалы.
- `js/timer.js` — экспериментальный раздел «Таймер».
- `js/tour.js` — подробное знакомство: тур по каждой странице с подсветкой элементов (`TOURS`, `tourStart`), окно «Знакомство» (`openTourMenu`), приглашение «Впервые здесь?» (`tourInvite`).
- `js/layout.js` — расположение: какие разделы включены и в каком порядке (`S.settings.secs`, `navSecs()`, `secOn()`), блоки Главной (`S.settings.home`, `HOME_BL`, `homeOrder()`), окна «Разделы» и «Главная».
- `js/ui2.js` — интерфейс: единая строка ввода, сворачиваемые блоки, экраны Главная / Задачи / Финансы / Привычки (`homeHTML`, `tasksHTML`, `financeHTML`, `habitsHTML`), знакомство при первом запуске.
- `js/pages.js` — страницы «Главная», «Профиль», «Настройки» (блоки настроек — `settingsBlocks()` в calendar.js), аватар `avatarHTML()`, достижения `ACH`.
- `js/cloud.js` — аккаунт и синхронизация: вход по коду из письма, запись в `user_data`, объединение изменений с разных устройств, выход и удаление аккаунта (см. «Аккаунты»).
- `js/input.js` — нажатия, клавиши, перетаскивание, свайпы. `js/share.js` — «Поделиться», копия в файл. `js/notify.js` — напоминания на устройстве (подписка, «Проверить», переход к дню по уведомлению), обновление раз в 30 с. `js/main.js` — запуск.
- Новое действие по кнопке: `data-act="имя"` в разметке + `ACT.имя = (el, ev) => …` в файле раздела (так каждое действие — отдельная функция для будущего ассистента).
- `sw.js` — service worker: офлайн-кэш (список `FILES` — все файлы выше) и приём пуш-уведомлений.
  **При каждом изменении файлов приложения увеличивай версию `CACHE` (`rem-vN` → `rem-vN+1`)**, иначе iPhone покажет старую версию. Новый файл — добавь в `FILES`.
- `manifest.json`, `icon-180.png`, `icon-192.png`, `icon-512.png` — установка на «Домой».

## Сервер (Supabase)
- Проект `zgasnvubcdprgsypkglh`, таблица `push_subscriptions` (endpoint, p256dh, auth).
- Edge Function `clever-task` отправляет пуш на все подписки. Ключи VAPID лежат в Supabase → Edge Functions → Secrets.
- **Защита (3 октября 2026).** Таблица `push_subscriptions`: RLS включён, одно правило «anyone can subscribe» (INSERT для anon); читать, менять и удалять чужие записи нельзя.
  - **С 9 октября 2026 таблица закрыта совсем** (`supabase/sql/push_lock.sql`): правил нет, у `anon` и `authenticated` прав нет, работает с ней только сервер. Причина — Security Advisor «RLS Policy Always True»: через открытое добавление кто угодно мог подложить свой адрес под рассылку. Подписка из приложения и так выключена.
  - `clever-task` запускается только владельцем: `isOwner` пропускает новый секретный ключ `sb_secret_…` в заголовке `apikey` (сверяется с `SUPABASE_SECRET_KEYS`) или старый ключ `service_role` в `Authorization`; остальным — 403 «Forbidden». Код функции — `supabase/functions/clever-task/index.ts` (копия того, что опубликовано в панели; публикуется кнопкой «Deploy updates»).
  - Проверено: publishable-ключ из приложения получает 403. Раньше он проходил и мог запустить рассылку всем.
  - Переключатель функции «Verify JWT with legacy secret» должен оставаться **включённым**: он проверяет подпись ключа.
  - Тестовая рассылка: Supabase → Edge Functions → clever-task → Test → Add header ▾ → Add secret key → Send Request. Поддельный JWT отвергает сам Supabase (401 «Invalid JWT»), проверено.
- С 3 по 9 октября 2026 подписка из приложения была выключена (`PUSH_SUBSCRIBE = false`): рассылка `clever-task` уходила всем подпискам сразу. С rem-v48 подписки личные — см. «Напоминания по времени». `clever-task` осталась тестовой рассылкой владельца.
- **Никогда не добавляй в репозиторий секретные ключи** (приватный VAPID, `service_role` / `sb_secret_...`). Репозиторий публичный. В index.html допустим только publishable-ключ.

## Как работать с пользователем
- Пользователь почти не программирует: объясняй по-русски, коротко и простыми словами.
- После правок: проверь, что JS без синтаксических ошибок, подними версию кэша в `sw.js`, затем коммит в `dev`, `git push origin dev` и `bash tools/deploy-beta.sh` — правка появится на **бете** https://beta.parsimony.ru за 1–2 минуты (см. «Бета и рабочая версия»).
- В `main` (рабочее приложение друзей, https://app.parsimony.ru) — **только когда пользователь скажет «выпускаем»**: `git checkout main && git merge --ff-only dev && git push origin main && git checkout dev`.
- Не создавай дубликаты файлов (вроде `index (1).html`).
- Показывай, что поменялось, и напоминай: на iPhone приложение нужно закрыть и открыть заново, иногда дважды.

## Решения по дизайну (уже согласованы)
- ПК: боковая панель слева в стиле Яндекс Календаря (заголовок, поиск, «+ Создать событие», мини-календарь, «Мои календари» = категории с галочками, «Шаблоны событий»).
- Вид «Неделя»: почасовая сетка на всю ширину (как в My Calendar), красная линия и подпись текущего времени, события пастельными блоками по времени, задачи без времени — строкой сверху. Клик по пустому месту — маленькое окно быстрого создания; полная карточка события открывается справа.
- Темы: светлая, тёмная, чёрная, «Авто». С 6 октября 2026 цвета задаёт палитра по выбору пользователя (см. «Оформление и подсказки»); прежние цвета — палитра «Классика».
- События в неделе перетаскиваются (мышью сразу, на телефоне — долгим нажатием ~0,3 с) и растягиваются за нижний край. Шаг — 15 минут. Клик по пустому месту выбирает время по четвертям часа (:00 / :15 / :30 / :45).
- Мини-календарь: под числом до 4 цветных точек — цвета категорий задач этого дня.
- Настройки → Категории: строка с цветным кружком (по нажатию палитра из 12 цветов + «свой цвет»), поле названия, удаление через значок корзины с подтверждением.
- Телефон: без боковой панели, вид «Месяц», свайп влево/вправо листает период, кнопка «Создать» в шапке. Плавающей кнопки «+» нет.

- Вид «День»: почасовая сетка одного дня + панель справа (на телефоне — снизу): прогресс «Выполнено X из Y», ближайшее событие «Дальше», быстрый ввод задачи на день (Enter), списки «Без времени» и «По времени».
- Esc закрывает всплывающее окно, боковую карточку и отменяет перетаскивание. Enter в быстром окне создаёт событие.
- Сетка недели/дня при открытии прокручивается к текущему часу и сохраняет прокрутку при обновлениях.

## Большое обновление графики (сделано 1 октября 2026, кэш `rem-v15`)
Ориентиры по просьбе пользователя: Notion Calendar (любимый — минимализм, тонкие линии, командное меню) и Яндекс Календарь (большая «Создать», календари с галочками, повторы, карточка с подписями слева). Не копия, а лучшее из обоих. Подробности — в `DESIGN-PLAN.md`.
- Дизайн-токены в `:root` (цвета тем, радиусы 6/10/14, тени, шрифт Inter с системными запасными). Красный `--red` — только «сегодня» и линия «сейчас».
- Шапка ПК — одна строка: заголовок (+ номер недели), «‹ Сегодня ›», переключатель Месяц/Неделя/День/Список, настройки. Телефон — две строки: ‹ заголовок › «Создать» ⚙ и переключатель + «Сегодня» + поиск.
- Виды: Месяц (на ПК — чипы событий и «ещё N», двойной клик создаёт), Неделя, День, **Список** (60 дней вперёд).
- Пересекающиеся события раскладываются в колонки (`layoutDay`). Короткие (≤30 мин) — в одну строку. Прошедшие приглушаются (настройка).
- **Повторы событий**: `repeat = {type: none|daily|weekdays|weekly|monthly|yearly, days:[0..6], until}`; выполнение повтора — `doneDates`, удалённые повторы — `skip`. Старый «повтор напоминания» переносится в `repeat` функцией `migrate()`.
- **Ввод фразой по-русски** (`parseNL`): «встреча завтра в 15:30 на час #работа», «в пятницу с 10 до 12», «через 2 часа», «12 октября». Работает в быстром окне, карточке, поле дня и меню команд.
- **Меню команд** Ctrl+K или «/» (поиск событий, команды, создание фразой). Горячие клавиши: N, T, M/W/D/L, ←/→, Ctrl+Z, Ctrl+Enter, Esc, ? — по `e.code`, работают в русской раскладке.
- Протягивание мышью по пустой сетке задаёт начало и конец нового события.
- «Отменить» в тосте и Ctrl+Z (`snap()` перед изменением) — для удаления, переноса, растягивания, создания, загрузки копии.
- Карточка события: Дата, Время (+ «Весь день»), Повтор, Календарь (цветные чипы), Напомнить (можно несколько — см. «Несколько напоминаний»), Место, Заметка; кнопки «Дублировать», «Удалить» (у повтора — «только это / все»), «В шаблоны».
- Настройки (теперь отдельная страница, см. ниже): тема (4 превью), размер сетки, начало дня, неделя с пн/вс, выходные, номер недели, приглушение прошедших, категории, уведомления (статус + «Проверить» = тестовое уведомление на устройстве), резервная копия в файл и загрузка из файла.
- Внизу боковой панели — «Настройки» и «Горячие клавиши». «Профиль» оттуда убран 6 октября 2026: он уже есть аватаром в шапке, а пользователь просил не повторять одно и то же. Раньше «Настройки» появились здесь по просьбе пользователя вместо строки «Уведомления: …»; статус уведомлений — в настройках). На ПК уведомления включаются без установки на «Домой», на iPhone — только из приложения с «Домой».
- Поля ввода на телефоне 16px, чтобы iPhone не увеличивал страницу.

## «Поделиться» (сделано 2 октября 2026, кэш `rem-v16`)
- Кнопка «Поделиться» есть в карточке события, у каждого календаря (боковая панель — при наведении; Настройки → Календари), «Поделиться всем календарём» и в меню команд.
- Ссылка `…/#share=<код>`: события сжаты (deflate-raw + base64url) прямо в адресе после `#`, на сервер это не уходит. Внутри: `k` — `e` событие / `c` календарь / `a` все календари; `dv` — метка устройства (`settings.dev`); `by` — подпись отправителя (`settings.name`).
- Из календаря отправляются только текущие и будущие события; заметки и место — по переключателю.
- Приём: окно «Вам прислали» с выбором, куда добавить. У копий есть поле `src` (`<dv>:<id>`) у событий и календарей: повторная ссылка обновляет копию, а не дублирует, и убирает будущие события, которые отправитель удалил.
- iPhone: ссылка из мессенджера открывается в Safari, у которого своя память, а не в приложении с «Домой». Поэтому в окне есть «Скопировать ссылку», а поиск в приложении принимает вставленную ссылку.
- Файл `.ics` (RFC 5545) — для Google / Apple / Яндекс Календаря: повторы, исключения, напоминание.
- Всё, что приходит по ссылке, проверяется (`fromShared`, `safeColor`) и выводится через `esc`.
- Логотип в боковой панели — листок календаря с сегодняшним числом (красный квадрат с числом путали со счётчиком уведомлений).

## Разделы «Задачи», «Привычки», «Финансы» (пробная модель, 2 октября 2026, кэш `rem-v18`)
Пользователь будет понемногу вносить правки. Ориентиры — в CLAUDE.local.md.
- Навигация: на ПК — пункты в боковой панели, на телефоне — вкладки внизу (`#tabbar`). Раздел запоминается (`settings.sec`). Короткая сводка в шапке телефона (`#secinfo`) убрана 6 октября 2026: она повторяла то, что видно на странице. Теперь `#secinfo` — просто пустое место.
- Цвета: у недель месяца свои пастельные цвета (`--w1…--w5`), цвета графиков `--c-blue…` заданы для всех тем и проверены на различимость. Один набор цветов на весь сайт.
- **Задачи** = события календаря с `task:true` и приоритетом `prio` (urgent/high/mid/low = Срочно/Высокий/Средний/Низкий), видны и в календаре. Дело без времени создаётся задачей. Неделя по дням с кольцом %, «Мои задачи» (срок, сколько осталось, приоритет, категория = календари), сводка, краткий список целей (раздел «Цели»), график «Поставлено / выполнено». Папок нет — решение пользователя.
- **«Вы пропустили»**: разовые дела за 30 дней без галочки; повторяющийся распорядок не показывается. Кнопки «Перенести» (сегодня/завтра/дата) и «Выполнено». Сам ничего не переносит.
- **Привычки** (`S.habits`): каждый день / по дням недели / раз в неделю / раз в месяц; недели месяца 1–7, 8–14, 15–21, 22–28, 29–31. Процент = отмеченные клетки / все запланированные клетки месяца до сегодня включительно, считая с 1-го числа месяца, в котором привычку создали (как видно в таблице; 3 октября пользователь заметил 50% вместо 33% при подсчёте с дня создания — исправлено); сравнение с прошлым месяцем; «Самые стабильные». Отметка задним числом — `settings.habitPast`. **Самочувствие** (`S.bio`): сон в часах, энергия/настроение/продуктивность/фокус/стресс 1–5, план и среднее; показатели настраиваются. Заметки на месяц — `S.hnotes`.
- **Финансы** (`S.fin`): каждая трата отдельной записью (`ops`), фраза «кафе 450», «+ зарплата 60 000», «такси 1,5к» (`parseMoney`, словарь `FIN_KW`). Разделы: Доходы, Подписки, Регулярные платежи (срок + «оплачено»), Траты, Накопления, Долги; бюджет на категорию одинаковый каждый месяц. Дневной лимит = (бюджет «Трат» − потрачено до сегодня) / дней до конца месяца.
- В «Финансах» над быстрым вводом — переключатель **Расход / Доход / Накопление** (`finKind`, категория угадывается только в выбранном виде: `parseMoney(текст, вид)`; незнакомый доход → «Прочие доходы») и кнопка **«Бюджет на месяц»** (`openBudget`: суммы всех категорий в одном окне, итоги «Свободно», добавление своих категорий по Enter). «задать план/бюджет» — ссылками в плитках и в колонке «Бюджет». **Свои категории** — «+ Своя категория» прямо в окне записи (сразу выбирается) и в окне бюджета (3 октября 2026, кэш `rem-v27`).
- Боковая панель ПК в каждом разделе: календарик (в «Привычках»/«Финансах» день открывает свой месяц, в «Задачах» — неделю) + свой блок: «Важные задачи» (срочные + шаги к целям), «Топ привычек» (по % за месяц), «Топ покупок» (самые дорогие траты месяца). На телефоне те же блоки — карточками в разделе.
- «Фокус месяца» и «Цель на год» (`S.focus`, `S.ygoal`) с 4 октября 2026 переехали в раздел **«Цели»** (см. ниже). Старые данные не удаляются: из них один раз собираются цели. Подпись пользователя «Это ваша самая грандиозная цель, вы же не будете жалеть потом?)» теперь среди подначек. Таблица задач на ПК прокручивается внутри.
- **Заметки** в «Привычках» — журнал `S.notes = [{id, date, text}]`: «Сохранить заметку» (или Ctrl+Enter) добавляет запись с датой, архив «Все заметки» по месяцам, правка/удаление, выгрузка в .txt. Старый текст `S.hnotes` переносится в журнал.

**Единая строка ввода** (`omniParse`, `omniHTML`, `openOmni`) превращает фразу в задачу, событие, деньги, привычку или заметку:

- явные начала: «заметка:», «привычка:», «задача», «событие», «доход 5000»;
- приоритет: «!» высокий, «!!» или «срочно» — срочно, «!низкий»;
- категория: `#тег`, иначе угадывается по названию календаря или по словам (`CAT_KW`); не угаданная — пунктирная метка.

**Как устроено.** `applyLook()` вызывается в начале `render()` и пересчитывает цвета только при смене настроек. Она ставит переменные на `<html>`:
- `--bg` — страница;
- `--page`;
- `--bg2`, `--sf`, `--line`, `--grid`;
- `--tx`, `--tx2`, `--mut`;
- `--acc`, `--accfg`, `--wm`;
- `--hov`, `--hov2`, `--wk`;
- `--card`, `--cardbd`, `--cardsh`, `--rc`;
- `--mix`, `--mixtx`.

Внутри `.card`, `.fold.fc` и `.gl-card` переменная `--bg` переопределена цветом карточки. Поэтому закреплённые колонки таблиц и поля совпадают с карточкой. Цвета графиков `--c-*`, `--good`/`--warn`/`--bad` и тени окон по-прежнему задаёт CSS (`css/app.css`). При смене системной темы в режиме «Авто» всё перерисовывается само.

**Подробное знакомство** (`js/tour.js`; просьба «расширенная версия знакомства — на каждую функцию, на каждую страницу»).
- **Как выглядит.** Затемнение с «окном» вокруг настоящего элемента и подсказка: заголовок, объяснение, «N из M», полоска, «Назад / Далее», ×.
  - Клавиши: стрелки и Enter — дальше и назад, Esc — выйти, Tab — только по кнопкам подсказки.
  - Прокрутка заблокирована. Правка пользователя: «на некоторых этапах можно перемещаться по странице», и подсветка съезжала.
    - `html.touring{overflow:hidden; scrollbar-gutter:stable}` убирает прокрутку полосой; разметка при этом не сдвигается.
    - Колесо и палец заблокированы по всему туру, в том числе над подсказкой.
    - Клавиши ↑ ↓ PageUp PageDown Home End и пробел не прокручивают.
    - Если что-то всё же прокрутилось (инерция, внутренние списки), `scroll` перерисовывает подсветку.
  - На ПК блок средней высоты, у которого подсказка не помещается ни снизу, ни сверху, подкручивается под шапку, подсказка встаёт под него. Наложение осталось только у блоков выше экрана: «Неделя» в задачах, подсказка в углу.
  - На ПК подсказка встаёт под элементом, над ним или сбоку.
  - На телефоне подсказка у верхнего края, а элемент прокручивается сразу под неё. Если не получается — подсказка снизу. Для шапки и вкладок — с противоположной стороны.
  - Проверено: на ширине 375 px ни один шаг не закрывает свой элемент.
- **Туры по страницам** (до 50 шагов): Главная 13, Календарь 9, Задачи 9, Привычки 8, Финансы 8, Настройки 5. В Задачах, Привычках и Финансах есть шаг «Настроить страницу».

## Безопасность (аудит 7 октября 2026, кэш `rem-v40`)
Пользователь особенно переживает за утечки и репутацию. Что проверено и сделано:
- **История репозитория (44 коммита)**: секретных ключей нет (`sb_secret_`, `service_role`, JWT, приватный VAPID, PEM). В коде только publishable-ключ Supabase.
- **Вывод на экран.** Пользовательский текст выводится через `esc()`: названия, заметки, имена. Подсказки графиков — через `textContent`.
  - Исправлено одно место без экранирования: подписи «пончика» в Финансах (`finance.js`, `esc(s.name)`).
- **«Поделиться» по ссылке** было безопасно и раньше: `fromShared` и `unpackShare` проверяют поля, `safeColor` — цвета, имена выводятся через `esc`.
- **Дыра: загрузка файла копии.** Данные брались как есть. Поддельный файл мог подсунуть кавычки и код в id, даты, цвета и числа — они вставляются в атрибуты без экранирования.
  - Теперь `importData` пропускает данные через `cleanTree` (`share.js`):
    - ярлыки (`CL_TOK`) — только буквы, цифры и `_.:#+-` (плохой id заменяется новым, остальное удаляется);
    - цвета — `safeColor`;
    - числа — `Number`;
    - ключи `__proto__`, `constructor`, `prototype` выбрасываются;
    - файл больше 30 МБ не принимается.
  - `migrate()` дополнительно чинит id и цвета календарей, id, дату (испорченная становится сегодняшней), название и время событий; `look.js` — тему.
  - Проверено «атакой»: файл с кодом в id, дате, названии, цвете, бюджете, теме и с `__proto__`. Ничего не выполнилось, лишних обработчиков в странице нет, приложение работает.
  - `cleanTree` нужно применять и к данным с сервера, когда появятся аккаунты.
- **Политика безопасности (CSP)** в `index.html` (`<meta http-equiv="Content-Security-Policy">`):
  - скрипты — только файлы сайта, никакого встроенного кода;
  - связь — только с сайтом и с `zgasnvubcdprgsypkglh.supabase.co`;
  - шрифты — Google Fonts;
  - картинки — свои, `data:` и `blob:`.

  Даже если где-то найдётся дыра, чужой код не запустится и не отправит данные наружу. Проверено: на всех страницах, в окнах и в туре нарушений CSP нет. **Новый внешний адрес (почтовый сервис, другой сервер) нужно добавить в CSP**, иначе запросы будут заблокированы.
- **Supabase сейчас:** `push_subscriptions` закрыта для приложения (9 октября 2026). `clever-task` — только владелец (см. «Сервер»).
- **Security Advisor (9 октября 2026):** ошибок нет. Осталось два предупреждения, оба ожидаемые:
  - `delete_my_account` — security definer: нужен, чтобы удалить себя из `auth.users`; удаляет только вызвавшего (проверено двумя аккаунтами);
  - Leaked Password Protection — паролей у нас нет (вход по коду), к тому же это платная функция.
- **Чек-лист перед раздачей друзьям** (повторять перед каждым выпуском):
  1. 2FA на GitHub, Supabase, reg.ru и почте пользователя.

  3. Два тестовых аккаунта: A не видит, не меняет и не удаляет данные B — проверка запросами с токеном A.
  4. «Вредные» данные во всех полях и в файле копии — ничего не выполняется.
  5. В консоли нет нарушений CSP.
  6. Поиск секретов в истории git.

  - После каждого `save()` (`SAVE_HOOKS`) — через 1,5 с. Ещё при открытии приложения, при возвращении в него, при появлении сети и раз в минуту — лёгкая проверка `rev`.

Все запросы из скрытой вкладки — с `keepalive` (до 64 КБ), браузер доводит их до конца, даже если iPhone «заморозил» приложение. Так событие, созданное прямо перед закрытием, успевает попасть в аккаунт, и сервер пришлёт по нему напоминание. Не совпала версия — обычный путь с объединением. Проверено подменой сервера.
  - Запись идёт только при совпадении версии (`PATCH … rev=eq.N`).
  - Если другое устройство успело раньше: забрать, объединить `merge3(база, это устройство, сервер)` и записать снова.
  - База — последняя общая версия (`remapp_v1_base`). Списки с `id` объединяются по записям, удаление побеждает, списки дат — как множества, в остальном побеждает это устройство.
  - Пока человек печатает, чужие изменения не накатываются.
  - Данные с сервера проходят `cleanTree`.
- **Первый вход.**
  - Аккаунт пуст → записи устройства уходят в аккаунт.
  - В аккаунте есть записи, а на устройстве нет → загружаются.
  - Есть и там, и там → окно «Объединить / Взять только из аккаунта». Во втором случае копия устройства сохраняется (`remapp_v1_safety`), её возвращает кнопка «Вернуть записи, которые были на устройстве до входа».
  - Данные устройства от другого аккаунта никогда не смешиваются.
- **Выход** — только на этом устройстве (`/auth/v1/logout?scope=local`; без `scope` Supabase выходит со всех устройств сразу). Сначала досылаются изменения; если нет связи — предупреждение. Затем данные с устройства стираются, остаются только оформление и «знакомство пройдено».
- **«Удалить аккаунт».** Подтверждение словом «удалить», затем `rpc/delete_my_account`.
- **Где в интерфейсе:** Настройки → «Аккаунт и данные», профиль → вкладка «Аккаунт». В тексте входа сказано, что бета закрытая и данные за пределами России.
- **sw.js:** файлы приложения берутся мимо кэша браузера (`cache:'no-cache'`, при установке `'reload'`). Новая версия приходит сразу, а не через 10 минут.
- **sw.js и переезд (rem-v46):** страница запрашивается с `redirect:'manual'`. Когда старый адрес отвечает «переехал» (301 на свой домен), браузер сам уходит на новый адрес вместе с `#share=…`. Прежняя версия в таком случае навсегда застревала на старом адресе со старой копией из кэша: обновить её нельзя, потому что `sw.js` тоже перенаправляется. Проверено на имитации переезда (два адреса локально) и без интернета. В кэш кладутся только ответы 200 без перенаправления.

## Напоминания по времени (9 октября 2026, кэш `rem-v48`)
Самое заметное, чего не хватало друзьям: «за час, за 15 минут» ставились, но уведомления не приходили.
- **Как устроено:**
  - Подписка устройства принадлежит человеку: `push_subscriptions.user_id`. Записывает её `rpc/push_register`, удаляет `rpc/push_unregister` (security definer). Читать можно только свои строки. Не больше 10 устройств на человека. Подписка переходит к новому аккаунту, если на устройстве вошёл другой человек. SQL — `supabase/sql/reminders.sql`.
  - Edge Function **`reminders`** (`supabase/functions/reminders/index.ts`, «Verify JWT» выключен — доступ проверяется внутри).
    - pg_cron раз в минуту (`supabase/sql/reminders_cron.sql`) вызывает её с секретным ключом из Vault (`reminders_key`).
    - Функция берёт `user_data` тех, у кого есть подписки, и находит напоминания, наступившие за последние 10 минут (`dueReminders`). Это переживает пропущенные запуски cron.

    - Вызов с токеном пользователя и `{"test":true}` — проверочное уведомление на его устройства, не чаще раза в минуту.

## Цели (4 октября 2026, кэш `rem-v30`)
Решения пользователя: шаги со сроком — **задачи** в «Задачах» и «Календаре».

«Цели» сначала были отдельным разделом. 4 октября 2026 (кэш `rem-v31`) пользователь решил: «всё-таки цели лучше пусть будут в задачах, не очень смотрится». Теперь в новом интерфейсе это **вкладка «Цели» внутри «Задач»**: Сегодня / Неделя / Все / Цели (`tView = 'goals'`, на вкладке — красный счётчик просроченных шагов). На этой вкладке:
- шапка «Цели», без стрелок недели;
- «+» создаёт цель: `SEC.tasks.newLabel`, `noNav`, `title`, `info` и `create` переключаются в `ui2.js`.

Все ссылки «Все цели →» ведут через `goGoals()` (`data-act="gall"`). `SEC.goals` больше не открывается как страница (его нет и в `SEC_ALL`): он хранит заголовок, сводку, «+ Цель», пример и боковой блок для вкладки.

**Данные.** `S.goals = [{ id, title, emoji, due, created, why, done, doneAt, steps }]`.
- Шаг без срока лежит в `goal.steps` как `{ id, t, done }`.
- Шаг со сроком — обычная задача (`task:true`) с полем `goal` = id цели. Поэтому он виден в плане дня, задачах, календаре и в «Вы пропустили».
- Если шагу без срока задать срок, он превращается в задачу.
- При удалении цели её шаги-задачи можно удалить вместе с ней или оставить обычными задачами.
- Ссылки на удалённые цели убирает `migrate()`.
- `S.goals` входит в `UNDO_KEYS` и в копию данных. Если загрузить старую копию без `goals`, цели заново соберутся из «Фокуса месяца» и «Цели на год».

**Страница** (`SEC.goals`, `noNav`):
- строка «Новая цель»: срок понимается из текста («до 1 июня», «через неделю»), затем открывается окно цели;
- карточка-подначка про просроченные шаги с кнопками «Завтра» и «✓»; если сегодня сделаны шаги — вместо неё похвала;
- карточки целей: значок, срок и сколько дней осталось, полоска, «N из M шагов», темп, «Дальше: …». При просрочке — подначка и «Перенести на завтра»; у просроченной цели — «+ неделя» и «+ месяц»;
- блоки «Достигнутые» и «Подначки и похвалы».

**Темп** (`goalStat`) сравнивает долю сделанных шагов с долей прошедшего времени от `created` до `due`. Варианты: «с опережением», «в графике», «отстаёте» (при любом просроченном шаге — тоже), «срок прошёл».

**Окно цели** (`openGoal`):
- название, значок;
- срок: дата и кнопки «Конец месяца», «Через 3 месяца», «Конец года», «Через год»;
- полоска, темп, подначка;
- шаги: отметка, срок («+ срок»), удаление; новый шаг вводится фразой («записаться на курс в пятницу» — сразу со сроком);
- «Зачем мне это»;
- «Цель достигнута» или «Вернуть в работу».

Изменения уже созданной цели сохраняются сами.

**Подначки и похвалы.**
- Подначки — `TAUNTS` (жёсткий сарказм без мата), похвалы — `PRAISE` (в том числе «Вы молодец!» и «Вы на шаг ближе к цели»). В тексте работают `{goal}`, `{step}`, `{left}`.
- Подначка одна и та же весь день для одной цели.
- Настройки — `S.settings.phr = { taunts, praise, custom:[{ id, kind, t }] }`: подначки и похвалы включаются отдельно, можно добавить свои фразы.
- Похвала приходит тостом, когда шаг отмечен. Отметку шага-задачи ловит `toggleDone` в `input.js` и вызывает `goalStepDone`. Когда сделаны все шаги, появляется подсказка отметить цель достигнутой.
- Подначка видна на странице «Цели», в окне цели и в окне «Вы пропустили» (`missedTaunt`).

**Связи с другими разделами:**
- Главная — блок «Цели» и кнопка «+ Цель». В новом интерфейсе блок открыт, когда цели есть; первыми идут цели с просрочкой.
- «Задачи» — краткий список целей; в «Важных задачах» вместо шагов месяца — «Шаги к целям».
- Боковая панель раздела — «Ближайшие шаги».
- У шагов в списках — метка цели `goalTag`.
- Строка ввода понимает «цель: … до …».
- «Показать на примере» добавляет 3 цели.
- Достижение «Большая мечта» — «Поставить первую цель».
